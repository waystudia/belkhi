# Белхи

Белхи — платформа для строительных тендеров. Заказчик описывает работы, сравнивает предложения и выбирает исполнителя. Контакты сторон открываются после согласования условий.

В планах проекта:

- Профили исполнителей с опытом, портфолио и отзывами.
- CRM для ведения строительных объектов и отслеживания этапов работ.
- Поиск субподрядчиков и поставщиков строительных материалов.

## Запуск кабинета заказчика

Из корня проекта выполните `python3 -m http.server 4178 --bind 127.0.0.1 --directory app` и откройте [локальное приложение](http://127.0.0.1:4178/).

Заказчик создаёт тендер и выбирает предложение. В кабинете «Исполнитель» можно сохранить профиль и специальности, найти опубликованный тендер, предложить цену и срок. Вкладка «Мои отклики» показывает решение заказчика. В демоверсии есть три тестовых заказчика, три специалиста и четыре заполненных тендера с тремя предложениями в каждом. Переключатель «Тестовый пользователь» находится в ленте и профилях; у каждого заказчика свои объекты и отклики. Примеры явно помечены «Демо».

В демоверсии тендеры, вложения, отклики и выбор сохраняются в IndexedDB. Профиль исполнителя хранится в localStorage. Открытые вкладки получают обновления через BroadcastChannel. Переключение тестовых пользователей предназначено только для проверки сценариев и не является входом в настоящий аккаунт.

Новые тендеры вошедших пользователей и их отклики сохраняются в Supabase (`belkhi_tenders`, `belkhi_tender_bids`), с локальной копией для CRM. RLS разрешает заказчику сравнивать все предложения своего тендера, специалисту читать только своё предложение; другой заказчик и гость не получают отклики. Выбор исполнителя разрешён только заказчику и только один раз; выбранный исполнитель обязан иметь отклик на этот тендер. В настоящие тендеры демонстрационные предложения не подмешиваются. Материалы до 15 МБ на тендер передаются вместе с публикацией. Старые локальные объекты автоматически в облако не переносятся. Обновление между устройствами происходит при открытии экрана или перезагрузке; Realtime пока не подключён.

## Установка на главный экран

Кнопка «На главный экран» запускает установку, когда браузер её предлагает, или показывает инструкцию для Safari и других браузеров. Манифест и service worker учитывают размещение в подпапке GitHub Pages. Запуск происходит в отдельном окне. Без интернета показывается страница с повторной попыткой; отправка откликов требует подключения. Service worker кэширует только статические файлы сайта, не Auth/API и не пользовательские вложения.

Проверки: `tests/pwa-demo-permissions.cjs` (роли, прямые ссылки, установка, offline и четыре ширины), `tests/tender-cloud-flow.cjs` (облачный сценарий через имитацию API), `tests/tender-permissions.sql` (реальные RLS-проверки внутри транзакции с откатом). Миграция: `belkhi_tender_ownership`. Фикстуры публичного демокаталога обновляются отдельно через `supabase/seed-demo-20261127.sql`.


## Демонстрационный каталог и управление

Откройте [каталог](http://127.0.0.1:4178/#catalog) или [кабинет владельца](http://127.0.0.1:4178/#admin). Каталог загружает тестовые объекты, людей и предложения из отдельных таблиц Supabase. Имя заказчика и аватары в публичном каталоге относятся к демонстрационным данным. Старые объекты и CRM остаются локальными; новые тендеры вошедших пользователей используют отдельные защищённые таблицы.

Владелец входит через Supabase Auth. Сервер проверяет роль в app_metadata. Разрешены создание, редактирование и удаление записей каталога, просмотр журнала и смена своего пароля. Удаление объекта или исполнителя удаляет связанные предложения. Изменения каталога фиксирует триггер PostgreSQL.

## Аккаунты и модерация

При открытии приложения доступны вход и регистрация по почте. Новый пользователь подтверждает почту кодом или ссылкой, создаёт пароль, вводит дату рождения и выбирает свободный @логин. Затем доступны «Стать заказчиком» и «Стать исполнителем». Выбор сохраняется в аккаунте. В настройках можно открыть оба профиля или изменить стартовый режим. Локальные данные CRM разделены по аккаунтам; новые тендеры и отклики синхронизируются с Supabase. Старые данные остаются доступны через «Демонстрационная версия» на экране входа.

На [странице администратора](http://127.0.0.1:4178/#admin) владелец с `app_metadata.belkhi_role = owner` может найти аккаунт «Белхи», посмотреть контактные и регистрационные данные, заблокировать или восстановить доступ к «Белхи». Запросы на блокировку и просмотры переписки требуют указания причины и записываются в журнал. «Демокаталог» открывает прежние инструменты управления примерами.

Для запуска серверной части примените миграцию `belkhi_account_moderation` и опубликуйте Edge Function `belkhi-moderation` с проверкой пользовательского JWT. Функция использует серверный ключ проекта, а браузер — только публичный ключ. Для пошаговой регистрации примените миграцию `belkhi_registration_identity`. Настройте доставку писем в Supabase Auth и добавьте адрес приложения в список разрешённых перенаправлений. Для писем подтверждения регистрации и входа по ссылке используйте `supabase/templates/registration-email.html`. Шаблон содержит и код, и ссылку.

Рабочая база Auth общая со SportPit. У приложений разные настройки регистрации. Для публичной регистрации «Белхи» с подтверждением почты нужен отдельный проект Auth с настроенной доставкой писем.

Просмотр переписки читает записи из `belkhi_messages`. Пользовательский чат пока не подключён. SMS и письма подтверждения учётной записи не являются сообщениями «Белхи».
