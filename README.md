# Белхи

Белхи — платформа для строительных тендеров. Заказчик описывает работы, сравнивает предложения и выбирает исполнителя. Контакты сторон открываются после согласования условий.

В планах проекта:

- Профили исполнителей с опытом, портфолио и отзывами.
- CRM для ведения строительных объектов и отслеживания этапов работ.
- Поиск субподрядчиков и поставщиков строительных материалов.

## Запуск кабинета заказчика

Из корня проекта выполните `python3 -m http.server 4178 --bind 127.0.0.1 --directory app` и откройте [локальное приложение](http://127.0.0.1:4178/).

Заказчик создаёт тендер и выбирает предложение. В кабинете «Исполнитель» можно сохранить профиль и специальности, найти опубликованный тендер, предложить цену и срок. Вкладка «Мои отклики» показывает решение заказчика. В дополнение к предложениям локального исполнителя показываются три примера с пометкой «Демо».

Обе роли работают в одном браузере на одном адресе приложения. Тендеры, вложения, отклики и результат выбора сохраняются в IndexedDB, профиль исполнителя — в localStorage. Открытые вкладки получают обновления через BroadcastChannel.


## Демонстрационный каталог и управление

Откройте [каталог](http://127.0.0.1:4178/#catalog) или [кабинет владельца](http://127.0.0.1:4178/#admin). Каталог загружает тестовые объекты, людей и предложения из отдельных таблиц Supabase. Имя заказчика и аватары в публичном каталоге относятся к демонстрационным данным. Обычные рабочие сценарии текущего прототипа используют локальное хранилище браузера.

Владелец входит через Supabase Auth. Сервер проверяет роль в app_metadata. Разрешены создание, редактирование и удаление записей каталога, просмотр журнала и смена своего пароля. Удаление объекта или исполнителя удаляет связанные предложения. Изменения каталога фиксирует триггер PostgreSQL.

## Аккаунты и модерация

При открытии приложения доступны вход и регистрация по почте. Новый пользователь подтверждает почту кодом или ссылкой, создаёт пароль, вводит дату рождения и выбирает свободный @логин. Затем доступны «Стать заказчиком» и «Стать исполнителем». Выбор сохраняется в аккаунте. В настройках можно открыть оба профиля или изменить стартовый режим. Рабочие данные прототипа остаются в отдельных хранилищах браузера для каждого аккаунта. Старые данные остаются доступны через «Демонстрационная версия» на экране входа.

На [странице администратора](http://127.0.0.1:4178/#admin) владелец с `app_metadata.belkhi_role = owner` может найти аккаунт «Белхи», посмотреть контактные и регистрационные данные, заблокировать или восстановить доступ к «Белхи». Запросы на блокировку и просмотры переписки требуют указания причины и записываются в журнал. «Демокаталог» открывает прежние инструменты управления примерами.

Для запуска серверной части примените миграцию `belkhi_account_moderation` и опубликуйте Edge Function `belkhi-moderation` с проверкой пользовательского JWT. Функция использует серверный ключ проекта, а браузер — только публичный ключ. Для пошаговой регистрации примените миграцию `belkhi_registration_identity`. Настройте доставку писем в Supabase Auth и добавьте адрес приложения в список разрешённых перенаправлений. Для писем подтверждения регистрации и входа по ссылке используйте `supabase/templates/registration-email.html`. Шаблон содержит и код, и ссылку.

Рабочая база Auth общая со SportPit. У приложений разные настройки регистрации. Для публичной регистрации «Белхи» с подтверждением почты нужен отдельный проект Auth с настроенной доставкой писем.

Просмотр переписки читает записи из `belkhi_messages`. Пользовательский чат пока не подключён. SMS и письма подтверждения учётной записи не являются сообщениями «Белхи».
